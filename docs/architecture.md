# 架构与实施边界

当前实现以 [Runtime v2](./runtime-v2.md) 为准。原有请求/响应工具循环已由持久化 Supervisor 替换。

## 进程与入口

tao/wry 承担 Windows 窗口和 WebView，React 通过 IPC 调用 AppController。
模型、Skills、Plugins、审批、事务内核和数据库都由 Rust 负责。
本版没有独立第三方 HTTP Gateway 或 CLI。
模型是纯文本单入口，不提供图片输入。

## 决策与执行

模型负责理解请求、检索、澄清和修订计划。
领域 Plugin 描述能力、资源和验证规则；Core 不理解领域文件格式。
程序校验真实能力与资源，处理授权、执行互斥、幂等提交、Job 等待和结果验证。
有序计划的普通步骤由程序连续推进，等待和重连不消耗模型决策轮数。
完整模型输出验证通过前不得执行工具。

## 状态与恢复

SQLite 保存运行、计划版本、调用尝试、审批、证据、事件与游戏实例执行锁。
状态变更和对应事件事务提交，revision 防止重复推进。
接纳响应丢失时仅在 Bridge 支持幂等的情况下重发原键；
已知 Job 在重启后对账；未知结果保留为待核对。
取消接口独立于游戏任务队列，未确认停止时不释放执行锁。

## 能力边界

当前产品装配为外部 BGI Agent，但 Agent Kernel 可替换领域 Plugin。真实 Bridge
仍需提供根目录总览描述的接口并完成实机契约验收。版本不匹配或缺少必要能力时拒绝调用。
本地语义描述符固定 methodId、版本、资源 Hash 和观测谓词，
不能用模型输出绕过绑定、扩大授权或执行任意表达式。

插件只能在启用后注册，失败时原子撤销本次注册；
模型可见的插件列表不包含凭据或启动参数。
MCP 使用单一异步响应分发器，Skills 读取受启用状态和目录边界约束。

插件自述的 `execution.effect: readOnly` 会跳过授权询问并进入只读并发批次，这是一条显式的
信任假设：已启用插件的声明被当作可信输入。自动放行的只读调用会写入 `plugin.readOnly` 事件
以便事后审计；要收紧这一点，只能不启用来源不明的插件。

用户配置、模型密钥、会话数据库和运行事件都保存在可执行文件目录的 `user/` 下；解析工作目录
从不参与，找不到可写的安装目录时会退回 `%APPDATA%\Sleepy Doll\user`，再不行才报错。
IPC 的 `bootstrap` 不返回密钥。会话与工具调用的建表由 `runtime/migrations.rs` 统一拥有，
`Journal` 是唯一的数据库所有者。`runtime_events` 中的流式帧在启动时由
`Journal::prune` 退休（帧内容已随助手消息落库），其余事件保留上限为 200000 条。
