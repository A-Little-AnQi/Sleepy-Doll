# Runtime v2 验证记录

日期：2026-09-08。模型输入已按用户要求限定为纯文本。

## 自动化验证

- Rust：43 项集成测试 + 31 项单元测试通过，包括配置、Schema、五种模型协议、运行状态机、
  授权、幂等、取消、恢复、消息归属、排队、计划执行、资源与 Skills、插件安装和 MCP。
- `cargo clippy --all-targets --no-default-features --features mock -- -D warnings` 通过。
- `cargo check --target x86_64-pc-windows-gnu` 通过，覆盖 Windows 托盘和 Wry 编译路径。
- TypeScript 类型检查、Vite 生产构建通过。
- 已修改前端文件的 Prettier 检查和 Git 空白检查通过。

关键故障用例：接纳后丢响应仍只产生一个 Job；重启恢复已有 Job 不重复动作；
取消模型请求不等待服务端完成；取消游戏 Job 确认后才释放执行锁；
过期观测不提交动作；未知结果不变成功；配置切换不丢旧运行取消入口；
禁用 Skill 后活动运行无法读取它；补充消息不会在完成竞态中丢失；
排队请求与答复按各自运行归属显示；两步计划只使用规划和最终答复两次模型决策。
此外覆盖插件工具执行语义：未声明影响类型时仍需授权，只有明确只读的工具免除
写授权并可进入并发批次，不一致的并发声明会在注册时被拒绝。
声明了输出 Schema 的工具在结果进入模型上下文前执行结构校验。

## 实际浏览器检查

在可见 Codex 浏览器的当前主题下检查了 1280×720 和 720×720：

- 新对话空态、短回复、长回复生成与完成状态。
- 对话内授权允许/拒绝、拒绝后的结束状态。
- 澄清、用户回答、下一条排队，以及排队后的正确答复顺序。
- 独立停止按钮、未知结果和核对恢复后仍保持未知。
- 会话切换返回、窄窗口导航、输入区和运行中操作的可达性。
- 模型配置没有图片上传或视觉开关；能力库显示新的本地插件管理入口。

发现并修复：发送图标与停止语义冲突、排队暂时切错活动运行、
澄清回答不进入可见消息、流式文本接管时闪烁风险、跨运行消息排序、
自动滚动影响整个页面、长侧栏把主行撑高导致输入区出屏，以及 WSL 文件事件
使 Vite 缓存空模块的问题。最后实测主内容高度和输入区底部均为 720px，
根容器顶部和文档滚动位置均为 0。

独立审查 Agent 完成了源码交互审查；其浏览器不可用，实际点击与截图由主 Agent 完成。
