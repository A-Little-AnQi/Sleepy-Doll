# Windows 定时任务接入设计

状态：插件后端和侧栏独立的“定时任务”页面已接入，包含时间设置、循环拨轮、任务库复制拖入、有序重复绑定和运行记录。AI 操作入口、必要问答和结果判断封装在插件技能内，本机时间及指定日期换算由受限接口提供。完整设计保留如下；当前可调用字段以[插件接口契约](../plugins/windows-scheduler/skills/schedule-task/references/api.md)和工具声明为准，当前范围见[插件说明](../plugins/windows-scheduler/README.md)。浏览器与隔离调用验证不代表 Windows 到时触发或 BetterGI 实机验收已经完成。

## 产品定位与首版范围

通过“定时任务”插件，为已经确定的动作增加执行时间。所有用户可见的导航、标签、弹窗、搜索和对话均使用“定时任务”；“Windows 计划任务”仅作为底层系统技术名称。AI 提交结构化参数，软件负责校验、注册、触发和记录结果。用户也可以手动创建，二者使用同一个后端服务。

一条定时任务由时间规则和有序执行项列表组成。支持单次、每天、每周、每月；设置页每条任务只配置一个执行时刻，每次触发均执行完整列表。既有多时刻任务仍按原规则运行；在设置页编辑保存时，先明确确认替换成当前单一时刻，不在读取或打开弹窗时自动迁移。列表可重复绑定同一个已有任务，每个执行项都是独立实例。按列表顺序逐项执行，单项报错或超时后仍继续尝试下一项。动作支持已有快捷任务和本地提醒，保留“已登记动作”扩展协议；任意程序、脚本及自由聊天提示词不作为默认可定时执行的动作。

“通用”体现在动作提供方可以扩展，不意味着向 AI 暴露任意 Windows 命令。以后确需启动外部程序，由用户在软件中登记程序及参数模板，再向 AI 暴露资源 ID 和有限参数；它需要独立的能力与权限设计，不以“运行程序”万能接口提前放开。

首版按本产品的管理员运行前提设计：由当前已提升的管理员账户注册任务，固定入口以该账户“使用最高权限运行”（`TASK_RUNLEVEL_HIGHEST`），使用用户已登录的交互令牌（`TASK_LOGON_INTERACTIVE_TOKEN`）。BGI 及其执行入口需要管理员权限，不能按普通权限设计整条执行链路。现有 `assets/sleepy-doll.manifest` 已声明 `requireAdministrator`；计划任务沿用同一固定程序入口，不另做普通权限启动器。

不保存 Windows 密码，不注册 SYSTEM，不提供账号或权限级别给 AI 选择。“最高权限”不能把普通账户变成管理员，注册时与运行时均须核验实际账户和提升令牌。Windows 的交互令牌只代表用户已登录，不代表桌面未锁定；游戏等动作另行检查桌面和宿主条件。低权限进程不能注册最高权限任务，依据 [Microsoft 的任务安全上下文说明](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)。

## 插件与模块划分

插件 ID 为 `windows-scheduler`，用户可见名称为“定时任务”。随软件分发，首次保持关闭，用户启用后注册工具；启用插件本身不创建任何系统任务。非 Windows 环境显示不可用原因。

建议文件归属如下，均为拟新增位置：

| 位置 | 职责 |
| --- | --- |

| `plugins/windows-scheduler/skills/schedule-task/SKILL.md` | 渐进式说明、何时选择动作、如何表达时间、结果含义及缺失参数询问。 |

| `src/runtime/` | 只增加通用的执行来源、受限调用范围和持久租约能力，不写 Windows 计划任务业务规则。 |
| `src/app/`、`src/main.rs` | 页面 IPC、插件生命周期、固定触发入口和运行实例交接。 |

计划、修订、触发记录和执行授权使用现有用户数据库及正式迁移，不在 `plugins/` 写运行数据，不另建平行配置事实源。Windows 中的任务定义是数据库计划的受控投影。

## 动作协议与不可绕过的边界

每个动作由可信注册表提供：动作 ID、提供方、用户标题、参数 schema、目标资源、是否允许定时执行、是否调用模型、交互条件、互斥资源、超时及结果核验方式。第三方清单中的自我声明不自动获得定时执行权限。

快捷任务适配器还要检查整个已发布流程：包括准备步骤、条件分支和每一个写入动作。只要包含任意命令、未登记写入、临时对象、交互问答、未知模型调用或不允许无人值守的步骤，就不进入可选列表。不能因为快捷任务“已经保存”就认定它可定时执行。

- AI 只传动作或资源 ID、公开参数和时间；不接收 exe 路径、命令字符串、XML、任务文件夹、运行账户、提权选项或任意工具名。
- JSON Schema 拒绝未知字段；后端继续检查资源归属、当前修订、参数语义和目标可用性。提示词不是权限边界。
- 对名称、提醒内容、参数体积、每用户计划数和创建速率设置明确上限；首版不接受秒级重复、无限重试或批量生成接口。达到限额返回可读原因，AI 不能修改限额或通过改名绕过幂等检查。
- 任务名称只是显示名称。系统任务路径由后端按当前用户、配置档 ID、计划 UUID 生成：`\SleepyDoll\<用户与配置档命名空间>\<计划UUID>`。不提供跨命名空间枚举、导入、修改或删除入口。
- 只有路径匹配还不够：修改和删除前还需校验本地归属记录、注册元数据、固定执行程序与动作指纹。外部改动记为“配置冲突”，不自动覆盖。
- 即使会话为“完全控制”，上述动作集合、参数限制和命名空间约束仍然成立。完全控制只影响审批，不扩展接口能力。
- 定时运行中拒绝创建其他计划、修改授权、加载新工具或访问超出绑定范围的目标。

本边界约束 AI 和低信任输入；不能把同一用户权限下的恶意本机代码当成被此插件隔离的对象。

## 对 AI 的工具契约

工具按需通过 `tools.search` 披露，不加入关键词硬路由。简短操作约定随插件启用装载；问答分支和完整参数通过 `skills.reference` 按需读取。下表描述设计职责，准确的当前参数见插件接口契约；不支持的未来能力不能作为已实现能力调用。

| 工具 | 输入重点 | 行为 |
| --- | --- | --- |
| `scheduler.clock` | 可选本机日期时间 | 只读返回当前本机时间、星期；将明确日期时间换算为带实际 UTC 偏移的单次执行时刻，不修改系统时钟或任务。 |
| `scheduler.actions.list` | 查询词、分页游标 | 从正式任务数据查询标题和内容，返回真实 ID、发布修订、命中摘要及绑定契约；同时用于右侧任务库和 AI 查找。 |
| `scheduler.list`、`scheduler.get` | 查询条件或计划 ID | 查询本插件所属计划、同步状态和依赖状态。 |
| `scheduler.preview` | 完整计划参数 | 纯只读，返回自然语言摘要、未来几次执行时间和不满足的条件；不持久化草稿。 |
| `scheduler.create` | 完整计划参数 | 校验、按现有权限审批、持久化、注册、读回核验；一次受控调用完成创建。 |
| `scheduler.update` | 计划 ID、预期修订、完整新参数 | 校验前后差异，防止陈旧表单覆盖；动作范围变化时重新建立授权。 |
| `scheduler.set_enabled` | 计划 ID、预期修订、布尔值 | 暂停或恢复；恢复前重新核验动作和授权。 |
| `scheduler.run_now` | 计划 ID、预期修订 | 沿用同一范围和互斥检查运行一次，返回独立触发记录。 |
| `scheduler.delete` | 计划 ID、预期修订 | 删除所属计划及其 Windows 投影，保留历史；不删除原快捷任务和宿主资源。 |
| `scheduler.history` | 计划 ID、分页游标 | 查询触发与实际运行记录。 |

查询和预览按只读工具处理。其他入口必须声明实际写入效果，不能为了免审批标成 `readOnly` 或仅有内部状态变化。授权依据由运行时注入，模型不能传 `approved: true` 自行放行。幂等键也由运行时或可信页面生成并在重试时复用。

创建参数示例：

```json
{
  "name": "晚间日常",
  "entries": [
    {
      "binding": {
        "kind": "shortcut",
        "shortcutId": "<真实任务A的ID>",
        "expectedPublishedRevision": 3
      }
    },
    {
      "binding": {
        "kind": "shortcut",
        "shortcutId": "<真实任务B的ID>",
        "expectedPublishedRevision": 1
      }
    },
    {
      "binding": {
        "kind": "shortcut",
        "shortcutId": "<真实任务A的ID>",
        "expectedPublishedRevision": 3
      }
    }
  ],
  "trigger": {
    "kind": "weekly",
    "weekdays": [1, 3, 5],
    "localTimes": ["20:00"]
  }
}
```

`entries` 数组顺序就是执行顺序，允许重复的 `shortcutId`；后端为每一项生成不同的 `entryId`，页面草稿也使用独立条目 ID。不得用任务 ID 作为列表唯一键，或按任务 ID 去重。重新排序、删除及错误记录均以执行项 ID 定位。创建后的查询结果返回这些身份，修改时保留未替换项的 ID。

单次使用带 UTC 偏移的 `at`；每天、每周和每月使用无重复值的 `localTimes` 数组。每周提供 1（周一）至 7（周日）的明确星期列表；每月提供 `daysOfMonth`（1–31）及 `lastDayOfMonth`，二者至少选中一项。重复触发跟随本机墙上时间，单次按已确认的绝对时刻执行。创建时解析并返回确定日期、时区和下一次触发，避免把“明天”“晚上”等原文保存为执行依据。

每月在当月不存在的日期跳过，例如仅选择 31 日时不在 4 月执行；选择“月末”则按当月实际最后一天执行。日期与月末重合时，同一时刻只触发一次。底层固定为全部月份，使用 [MonthlyTrigger](https://learn.microsoft.com/en-us/windows/win32/taskschd/monthlytrigger) 的日期及月末能力，不把系统位掩码暴露给 AI。多个时刻映射到同一个 Windows 任务的 [TriggerCollection](https://learn.microsoft.com/en-us/windows/win32/taskschd/triggercollection)，始终只启动固定程序并传同一个计划 ID，不按执行列表各项创建多个系统任务。夏令时和重复本地时刻由入口按确定的到期规则过滤，预览与触发计算共用同一规则，并与 Windows 的下一次运行时间核对。

成功结果应包含 `scheduleId`、修订、`enabled`、`registration: verified`、下一次执行时间和自然语言摘要。需要审批返回待审批状态；注册结果不明返回 `unknown` 和可追踪的操作 ID，不能伪装成功或让 AI 换个名字重试。

## 权限与未来执行授权

管理计划沿用软件原有模式：只读模式不能写；请求审批模式显示具体操作卡片；完全控制模式可以直接完成已明确的请求。手动表单点“创建并启用”本身即为该具体计划的用户操作，不再弹相同内容的二次确认。

Windows 管理员权限和 AI 的操作授权是两层检查。管理员进程提供操作 BGI 和注册任务所需的系统权限，AI 仍只能调用受限接口。运行账户、`RunLevel` 和固定程序路径均由后端决定，不纳入模型参数。

注册前检查当前进程的实际提升状态和账户身份；只有实际未提升并阻塞操作时才返回“需要以管理员身份运行 Sleepy Doll”，保留表单输入且不创建半成品任务。正常启动由现有程序清单交给 Windows 处理 UAC，不在每个工具调用内反复执行提权命令，也不在定时触发时临时弹 UAC 等待确认。被取消的系统授权不能被 AI 的“完全控制”设置覆盖。若用户在 UAC 中换成其他账户，需按该账户的配置档和任务归属重新核对，不能冒用原账户的计划。

创建已启用计划时，同时持久化一份定时执行范围：计划修订、动作提供方、快捷任务发布修订、规范化参数指纹、目标资源身份和内容版本、允许效果、运行条件和超时上限。目标内容版本由提供方的真实版本号或规范化快照指纹核验，不能只比较快捷入口的名称；无法核验必要范围的动作不获得无人值守资格。它只授权此计划未来按约定触发，不授权 AI 做额外操作。已有 `TrustGrant` 不能原样当作这份精确授权，需要专门记录或扩展契约。

绑定范围还包括每个 `entryId`、绑定修订及有序执行项列表的指纹，重复绑定分别授权。计划触发必须以 `Scheduled` 来源携带这些范围，在每个执行项开始前检查，不能直接走“SavedWorkflow 一律 FullAccess”的分支。某一项的目标改版、删除、参数或契约变化时，只将该项记为无法执行并继续下一项，不默默使用最新版本。整条定时任务的授权被撤销、插件停用或用户停止时才终止整轮。重新保存设置后建立新的有序范围，已经开始的轮次继续使用自己的不可变快照。

会话审批模式控制当前 AI 的管理调用；已启用计划的未来执行依赖这份持久授权。用户要停止后续定时执行，应暂停计划或停用插件，不能把会话模式切换暗当作全局暂停。

## 创建与触发链路

```text
用户请求 / 手动表单
  → 选择已登记动作，读取目标与时间
  → 统一 ScheduleService 校验、摘要与现有权限处理
  → 写入待注册记录及精确执行范围
  → 已提升进程通过 Windows COM 注册最高权限任务，读回定义并核验
  → 完成持久状态，页面与对话收到同一结果

Windows 到时触发
  → 以最高权限启动固定路径的 sleepy-doll.exe --run-schedule <不透明计划ID>
  → 核验实际管理员令牌、固定配置档、账户和会话
  → 向同账户、同配置档的管理员执行实例交接，或建立管理员后台执行实例
  → 检查插件开关、计划修订、授权、实际到期时间及依赖
  → 取得触发幂等键和持久资源租约
  → 按本轮快照的 entryId 顺序逐项执行，单项错误隔离后继续
  → 记录跳过 / 已提交 / 运行中 / 成功 / 失败 / 结果未知
  → 页面与通知读取同一份记录
```

固定入口中的配置档引用由注册器生成和校验，不允许 AI 指定配置文件路径。任务参数中不保存密钥、对话、JSON 动作内容或用户输入的命令。程序路径来自经核验的本机安装，不通过 PATH 查找或 shell 拼接。底层使用 Rust 的 Windows Task Scheduler COM 接口，明确加入所需的 `windows` feature；不向 AI 暴露 PowerShell 或 `schtasks`。

应用已运行时，通过限定当前 SID、登录会话和配置档访问的命名管道提交计划 ID；执行接收方还必须经过实际提升令牌与可信程序身份核验，不能把管理员启动的任务交给普通权限实例执行。首版主程序本身要求管理员权限；若发现旧版或开发环境的普通权限实例占用相同配置档，返回明确冲突，不静默降权或创建第二个数据库所有者。人工管理界面提供退出旧实例后以管理员身份重新打开的指引；定时触发记录冲突失败，不等待交互提权。

应用未运行时，最高权限的固定入口创建同一互斥所有者及最小后台运行环境，不打开聊天页。入口提升核验失败立即停止执行，不能把 Windows 已成功启动进程当成权限满足。该单实例、唤起和后台入口目前均需实现和验证，不能把打开普通窗口当成完成支持。新入口不复用尚未稳定的实验性 Agent Host 协议。

### 一致性和重复触发

Windows 注册和数据库提交没有共同事务，需要持久操作记录与恢复流程。建议状态为 `registering → active`，修改时为 `updating`，失败为 `error` 或 `conflict`。先持久化操作、生成禁用任务、读回核验，再切换生效状态；恢复流程只处理本插件且代次匹配的对象。所有触发先经过数据库状态闸门。界面在系统注册核验完成前不将 switch 稳定切为开启；接近首次触发时的启用竞态需由宽限检查或明确的下一次生效时间处理，不能声称实现了分布式原子提交。

Windows 层使用 `IgnoreNew`；应用层按计划修订和应触发时间生成唯一键，并对快捷任务、宿主等目标资源取得持久租约。两份计划同时指向同一资源也不能重入。Windows 的实例策略只覆盖它启动的进程，启动器退出后仍需应用租约约束真实任务；参见 [MultipleInstances](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-multipleinstances)。

宿主只确认接收时，记录“已提交”，绝不写成“执行成功”。若需要避免与后续真实宿主运行重叠，必须有可查询的宿主忙碌状态或可验证完成信号；没有就不提供该动作的无人值守资格。超时或退出时不能直接释放状态未知的宿主占用并再次提交，必须先核对宿主状态。

### 有序执行、重复绑定与错误继续

设置弹窗中的执行列表是运行顺序的唯一依据。右侧任务库的排序、筛选及外层定时任务汇总列表的顺序都不改变它。一项绑定一个既有快捷任务时，该任务内部原有步骤仍按其自身契约运行；设置弹窗不拆散或改写原任务。A → B → A 表示三次独立执行，第三项不能因第一项用过 A 就被去重或复用结果。

需要新增独立的定时执行队列协调器，持久化每轮 `occurrenceId`、执行项快照、游标及逐项结果。每项在开始前拥有独立 `entryId`、子运行 ID、取消令牌、准入等待上限和执行时限；幂等键至少包含 `occurrenceId + entryId`。同一项因网络或程序恢复重试提交时不能多运行一次，同一任务在不同项中出现则必须得到不同的子运行。

现有快捷任务执行器不能直接代替这个协调器：`ContinueIndependent` 只覆盖部分错误路径，快捷任务的非成功结果会设置后续停止标记，预算检查和部分初始化错误也可能从外层直接返回。新协调器将每个快捷任务作为独立子运行，捕获该项的提交失败、返回错误、失败终态、超时及结果未知，写入该项后继续循环；不会把单项错误传播成整个列表停止。保留快捷任务原有的内部失败策略，不为实现外层继续而偷偷修改用户的原任务。

```text
为本轮固定 entries 快照
for entry in entries:
    若用户停止、插件停用或整轮授权失效：停止整轮
    在本项的期限内，提交并跟踪它的真实运行结果
    捕获本项错误或超时，进行有界的清理并记录结果
    继续下一项
汇总全部逐项结果，而不是只返回最后一项结果
```

上一项正常运行时等待它完成，再启动下一项；“已提交”不是完成证据。仅提交即返回的快捷任务，需要提供方的完成观测适配器跟踪本次宿主运行，不能原样把“已提交”视为可启动下一项。记录中的 Job 等临时标识属于本轮结果，不写回任务绑定。

本项超时后只取消它自己的子运行，清理有明确时限，随后仍推进列表；不能取消整轮令牌，也不能无限等待宿主停止。每项有独立预算，不能沿用首项的默认运行期限把后续整列提前截断；整轮及 Windows 任务的执行期限按已批准的逐项上限和清理开销计算并明确校验。宿主若仍未确认停止，保留它的真实占用状态。后续每一项仍执行自己的准入检查：使用同一忙碌资源时记录该项无法启动，再继续后面的项；使用其他可用资源的任务正常执行。错误继续不伪造资源空闲，也不把剩余整列统一标成跳过。

`submit_workflow` 当前会合并到相同目标的已有活动运行，定时队列需要增加携带调度来源和执行项身份的提交路径。已有不属于本项的运行应明确返回目标忙碌，不能作为本项的新运行返回。每个执行项独立校验其精确修订，不能在开头因某一项失效就提前拒绝整轮。

运行历史按执行项记录成功、失败、超时或结果未知；混合结果显示完成了哪些项、哪些项有错误。用户主动停止时才把尚未开始的项记为未执行。宿主进程或软件整体崩溃需要依靠持久游标恢复：先核对正在执行项的外部状态，防止重复有副作用的调用，再推进后续项；不能声称普通异常捕获能在进程崩溃后继续。数据库无法写入时需明确报告调度器故障，不能丢掉记录后盲目续跑。

### 运行条件与时间规则

- 首版固定“错过时跳过”，不补跑历史任务，不自动唤醒电脑或重试有副作用的失败动作。触发入口仍核对实际到期时间及明确的调度宽限，防止迟到的启动被当作正常触发。
- 不把 `StartWhenAvailable` 描述为开机后立即补跑；该选项有适用条件且可能排队延迟。以后增加补跑需要独立的宽限、去重和次数规则，参见 [StartWhenAvailable](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-startwhenavailable)。
- 登录及管理员条件由 Windows 和入口共同检查。游戏动作另查会话是否锁定、远程会话是否可交互、宿主连接及目标忙碌状态；条件不满足记录明确原因。正常执行通过已注册的最高权限任务启动；失败后不尝试其他账户、降低 UAC、解锁桌面或更改游戏配置。
- 提醒可按自身的会话条件投递；通知已经提交与用户已经看到是不同结果。应用退出时的提醒必须验证通知注册和投递，不能只在窗口内弹 Toast 冒充后台提醒。
- 停止分为停止后续触发和停止已运行任务。暂停不默认终止当前运行；取消使用真实动作的停止接口，并保留结果核验。

## 页面与交互

沿用现有浅灰侧栏、白色内容区、灰色分段标签、黑色主按钮和共享控件；明暗主题都使用正式设计变量。生图仅作视觉评审，不表示交互已实现。

严格遵守必要性原则：页面只展示用户当前需要识别、选择、编辑或处理的信息。后端必须处理的约束不自动成为界面文案；一个控件已经表达的信息不再另加标签重复解释。管理员权限、正常连接状态、固定运行条件、默认跳过和互斥策略由软件处理，不常驻展示。只有实际异常或用户主动查看记录时，才显示具体原因和可用处理入口。

### 入口和列表

侧栏“快捷任务”和“定时任务”是平级入口。快捷任务页内仅保留“已保存任务 / 运行记录”；定时任务页有独立标题、搜索与“新建定时任务”。已保存任务卡片和右栏的“安排时间”会跳转到独立定时任务页，打开设置弹窗并预先加入该任务。外层只负责汇总、启停和打开设置，不新增任务库、双栏编排或全局任务排序。

工具栏仅保留“搜索定时任务”与“新建定时任务”。每行保留名称、执行顺序的简短摘要、执行时间、switch 和更多菜单；摘要与名称相同时不重复。多项摘要可显示“A → B → A”，过长时截断并在打开设置后完整展示。switch 单独表达启停，不再放“已启用／未启用／已暂停”等徽标，也不常驻解释开关状态。执行时间直接显示“每天 20:00”等规则；默认不再重复显示“下次：今天 20:00”，需要精确下一次时间时由用户主动查看。

不新增“管理员运行”“Windows 计划任务 · 已连接”等正常状态标签，不展示功能介绍副标题、页底关机提示或固定运行条件。删除默认展开的下方详情区；整行的标题、说明和空白区域点击切换启停，开关只触发一次；更多按钮及整行右键打开同一菜单，提供编辑、立即运行、运行记录及删除。菜单开合使用可中断的动画；关闭菜单的点击和退场期间的点击不传给行开关。仅在实际异常影响执行时就近显示原因，不能用开关的开启状态冒充依赖正常。

窄窗口允许目标摘要和执行时间换行，操作区仍可见，不为首版增加第三栏。列表与表单使用相同数据和 IPC，不各存一份计划状态。

插件关闭时保留记录。此页不展示独立的插件启用入口，创建、恢复及手动管理任务时由同一操作接通插件；插件总开关仍归工具与扩展。没有定时任务时，空状态在所属剩余内容区水平、垂直居中。冲突、目标失效和没有匹配结果各有明确说明，不能都显示成空列表。

### 时间的实际设置方法

| 模式 | 显示控件 | 用户操作与保存含义 |
| --- | --- | --- |
| 单次 | 日期输入、日历按钮、一个时分控件 | 点击日期展开月份日历，左右切月并点选日期；也可直接输入年月日。时间使用 24 小时制，保存成明确的带偏移时刻。 |
| 按天 | “每 N 天”输入与一个时分控件；N 大于 1 时显示开始日期 | N 为 1–365 的整数，1 表示每天；每两天以开始日为基准，固定本机时刻，跨周、跨月不断开。开始日期和时间左右等宽，单击选择、双击输入；编辑、停启不重置起算日，错过的时刻跳过。 |
| 每周 | 周一至周日的七个多选按钮、一个时分控件 | 点选需要的星期，如一、三、五；至少一个。选中的每一天在该时刻执行完整列表。 |
| 每月 | “每月几号”日期选择器、一个时分控件 | 日期选择器展开 1–31 的多选数字网格及“月末”，可选择一个或多个日期。至少选一项，关闭后用“1日、15日”等紧凑摘要表达；没有该日期的月份跳过，月末使用实际最后一天。 |

日期和时间控件在指定日期、按天间隔及每月模式中左右等宽，各占一半；普通每天、每周只在左半边保留一个时间框，极窄窗口才改为上下排列。日期、时间框单击打开选择器，双击进入键入模式，Enter 确认、Esc 撤销。小时、分钟范围为 00–23 和 00–59，允许任意分钟。双列循环拨轮以用户提供的手机闹钟为交互参考：中间一行是选中值，数字较深且略大，上下各约两行逐渐淡出；不显示滚动条，也不把选中项画成普通下拉选项的黑色方块。只借鉴选择行为，仍使用软件自己的字号、灰白配色和弹层样式。

小时列和分钟列均可按住鼠标上下拖动，释放后吸附到最近一行并更新当前值；滚轮、触控板、点击相邻数字和键盘上下键也可调整。两列分别无限循环，23 的下一项是 00，00 的上一项是 23；分钟同理 59 与 00 相邻。分钟跨界只改变分钟列，不隐式进位小时或日期。拖动超过阈值后屏蔽该次释放产生的点击，不让一次拖动又误选另一行。

拨轮吸附后的值同步到弹窗草稿。Enter 或点弹层外部结束选择，Escape 恢复打开拨轮前的时分；不再按“选到分钟即自动关闭”的旧下拉框行为处理。直接输入在合法失焦时提交；非法值就近提示并阻止保存。点最终保存时先结算仍在吸附的拨轮位置，不能保存旧值。选择弹层受弹窗边界约束，不盖住底部确认按钮，也不把手机的额外说明或按钮复制进来。

实现为共享的循环数字列控件：维护逻辑索引、固定行高和拖动偏移，只渲染当前中心附近的数字；显示值用非负取模 `((index % count) + count) % count` 得到。跨行时重置局部位移并更新索引，保持视觉连续，不靠一个有限列表滚到底后跳回，也不堆积无限 DOM。使用 Pointer Capture 追踪鼠标拖动，逐帧更新位移，结束时吸附；取消、关闭弹窗和卸载均释放捕获并停止动画。拨轮手势与任务拖放分开命中，不得把拖时间当成拖任务。两列内部处理滚轮事件而不带动整个设置弹窗；隐藏滚动条不能牺牲鼠标拖动、键盘及直接输入能力。

单次日期日历显示星期表头、当前月份和可选日期；过去日期不可选择。当天已过去的时刻不得保存成单次任务。每周的选中状态由星期按钮自身表达，不再写“已选周一”等标签。每月的 1–31 是每个月的日序号，不按当前月长度禁用 29–31；仅在选择了这些特殊日期时就近说明短月的实际行为。切换单次、每天、每周、每月保留各模式未保存输入供切回，但提交时只发送当前模式的字段。

时刻可移除和重新编辑；只剩一个时刻时保留可编辑的输入位置。时间值按时刻排序且不允许重复，任务执行列表则严格保持用户拖动的顺序。时区遵循既定本机规则，不额外展示无法修改的说明。时间缺失、日期失效或未选星期时，只在相应操作后给出必要校验，不用大块提示占据编排空间。

### 任务库搜索、复制拖入与内部排序

右侧标题为“任务库”，顶部搜索框占该栏宽度，提示为“搜索标题或内容”。搜索范围至少包含任务名称、描述、已发布步骤标题、目标名称和已保存的公开任务内容；不能只查名称。命中内容时展示相关的一行摘要，辅助区分同名任务。索引来自当前正式任务数据，不搜索聊天历史或凭据，不让模型生成候选。

任务库是可重复取用的源列表：拖入执行列表后，原卡片不消失、不置灰、不打“已添加”标记，也不因已使用就被搜索过滤。库条目按真实任务 ID 和发布修订定位；即使同名，也不靠标题绑定。

库条目拖入左侧时，以 `copy` 语义创建新的 `entryId`，不移动源任务。指针进入执行列表后，在行间显示插入线，松手在该位置插入；进入空列表时整块区域可接收，空状态仅提示“从右侧拖入任务”。拖到最后一项下方即追加。拖回库、拖到无效位置或按 Escape 取消时，不改变任何列表。

左侧每行显示拖动柄、从 1 开始的顺序号、任务标题、必要的目标摘要及移除按钮。拖动既有项使用 `move` 语义，仅移动该 `entryId`；松手后重新连续编号。A → B → A 的两个 A 有不同的 `entryId`，删除其中一个不影响另一个，更不删除右侧任务。仅在拖动期间显示拖动影像和插入线，不长期展示装饰箭头或拖放说明。

同一个库条目连续拖入两次必须产生两行；搜索后再拖入也一样。搜索只改变右侧候选，不修改左侧编排。筛选、任务库刷新和拖动并发时按开始拖动时的真实身份校验，不能把同一行位置误绑定到更新后的另一项。外部文件、任意文本或未知拖动类型不能变成执行项。

键盘可聚焦库条目后 Enter 追加一份；左侧拖动柄支持键盘上下移动及取消，移除只针对本条执行项。鼠标与键盘都使用同一个插入／移动／移除状态更新逻辑，不能出现键盘添加自动去重而拖动允许重复的两套行为。

上述操作只修改弹窗本地草稿。点击“创建并启用／保存更改”才统一校验时间、有序绑定和精确修订，然后注册系统任务；不会在拖动时执行源任务或修改原快捷任务。提交失败保留草稿，任务库刷新不会覆盖左侧顺序。用户关闭时仅对未保存修改作必要确认。新增条目的参数若必须填写，直接在该项展开所需字段，例如提醒内容，不另造一层聊天流程。

实现上使用区分 `libraryTask` 和 `queueEntry` 的拖动数据、独立 `entryId`、明确的插入索引及统一草稿 reducer。React 的 key 使用 `entryId`，不得使用重复的任务 ID 或数组索引。可复用现有 Pointer Events、拖动影像和命中行边界的模式；必须新增跨两栏的复制插入语义，不能把现有侧栏的移动操作直接照搬。只有库区域和队列区域各自滚动，拖动靠近边缘时滚动对应区域；不能让拖动导致整个弹窗跳位。

### 对话创建

用户说“每天晚上八点运行日常快捷任务”后，AI 读取真实候选并核对目标，解析为本机时间 20:00，再调用受控创建接口。只有目标或时间有实质歧义才询问。

请求审批模式下，用现有操作卡片简明展示触发时间和真实有序列表，例如“每天 20:00：A → B → A”，允许编辑或确认；不重复铺陈固定运行条件。完全控制模式在目标明确、参数合规时直接注册并返回结果。回复应为“已创建定时任务，每天 20:00 依次运行……”，附“查看定时任务”；不能把未完成注册的草稿回复成已创建。页面表单不嵌聊天历史和工具参数。

### 暂停、删除、运行记录与插件生命周期

开关需在系统修改和读回核验成功后才稳定切换，失败回滚视觉状态并说明原因。删除界面说明删除的是时间安排，不影响原快捷任务；已有运行继续显示并提供独立停止入口。

运行记录增加“手动 / 计划触发”来源筛选。每次触发保存计划修订、计划时间、实际触发时间、动作及修订、应用运行 ID、宿主运行引用、结果和跳过原因；计划改名或删除后仍能查看原始快照。计划管理状态与运行结果分别显示，不以 Windows 进程退出码替代业务完成证据。

停用插件先使执行闸门失效，再停用其所有已核实归属的 Windows 任务，保留数据及历史；部分失败明确列出未同步项，固定入口仍因插件停用拒绝执行。重新启用插件不自动恢复此前停用的计划，需要用户选择恢复。正在运行的任务不默认被强行终止。

安装更新要核验固定程序路径及计划兼容性，迁移失败暂停相关计划；换安装目录不能留下指向旧 EXE 的活动任务。卸载只清理可证明归属的系统任务，保留用户数据的策略沿用安装器；不得扫描删除其他软件的系统任务。

## 实施顺序与验收条件

1. 先实现强类型计划、合格动作注册表、精确执行范围、数据库迁移及纯只读预览；覆盖任意路径／XML／未知工具／未授权动作拒绝和修订变化。
2. 实现 Windows COM 注册、修改、暂停、删除和读回核验；验证命名空间、当前管理员账户、`Highest` 与 `InteractiveToken`、实际提升令牌、失败恢复与外部篡改冲突，确认无越界系统任务修改。未提升进程必须明确失败，不落入普通权限注册分支。
3. 实现固定触发入口、管理员实例交接、跨进程租约、确定性执行和宿主结果回写。此阶段验证应用打开与关闭两种情况，并验证同一快捷任务被不同计划同时触发；额外验证普通权限旧实例占用时不会降权执行或抢占数据库。
4. 接入插件 MCP、现有权限模式和页面 IPC；补齐外层汇总、设置弹窗里的时间设置与双栏拖放、快捷任务“安排时间”及对话操作卡片。任务库搜索必须有真实内容命中，不以仅标题筛选代替。
5. 实际 Windows 验收：单次／每日／每周／每月、重启应用、重启电脑、锁屏、未登录、睡眠错过、时区变化、依赖关闭、任务改版、更新安装路径及插件停用。确认到时启动的是管理员进程，并实际调用管理员运行的 BGI；同时覆盖 UAC 取消、非管理员账户和提升状态不符。测试使用明确登记的隔离计划和用户数据，结束后只清理本任务对象。

首版交付门槛是“参数创建 → Windows 实际注册且读回一致 → 时间到达 → 应用开关两态均能进入正确动作 → 业务状态真实展示 → 暂停和删除生效”。单元测试通过、界面能打开或任务进程退出码为零都不能单独证明此链路完成。

必须另外验收以下具体行为：

- 右侧同一任务拖入两次后源卡片仍在、仍可拖，左侧得到不同 `entryId` 的两项；运行记录中确实有两次独立执行，不能只看到两行 UI。
- 将 B 拖到 A 前后，保存并重新打开保持顺序；触发后的真实提交与终态记录按新顺序发生。移除一个重复项不会移除另一个或原任务。
- 名称不含关键词但内容包含的任务能被右侧搜索找到；搜索不改变左侧列表，清空搜索仍能继续重复拖入。
- 第一项实际返回错误，第二项实际收到执行调用，第三项重复执行第一项的源任务；逐项结果分别记录。超时、目标缺失、参数失效和依赖不可用也分别覆盖。
- 未确认停止的宿主仍占用资源时，后续项各自执行准入检查，独立资源项仍运行；不能将“已经遍历列表”当成“每个目标都成功启动”。
- 用户停止会阻止后续项；单项报错不会触发用户停止语义。逐项期限不消耗掉后面所有任务的执行机会。
- 实际点选单次日期、小时和分钟、每周多选星期，每种模式只有一个执行时刻；另验既有多时刻任务的取消与确认替换，取消不得写入。保存、重开、注册和到时触发的数据一致。宽窄窗口都验证拖入、排序、滚动、时间弹层及固定底部按钮。
- 每月覆盖多日期、31 日、平闰年的 2 月、月末以及日期与月末重合，核对实际触发次数。循环拨轮覆盖鼠标拖动、滚轮、触控板、点击、键盘和直接输入；双向跨过 23／00 和 59／00，无边界跳变、误点击或日期进位。
- 确认时分拨轮没有可见滚动条，选中数字始终吸附在中间；松手后和点保存时的值一致。关闭或取消后没有 Pointer Capture 或动画残留，拖拨轮不触发任务排序。
