# 创建快捷任务

用户要「创建快捷任务」「把某项加成一键入口」，或调整某个已有入口时按本手册执行。

1. 以本轮明确的操作目标为准；既有应用任务、配置和资源核对真实引用，通用本机操作核对目标路径、参数和范围后保存工具组合，不要求先建立应用配置或预先执行一次。原对话仅作定位依据。查找或修改已保存入口，用 `shortcut.list` → `shortcut.get` 取得真实 id、当前绑定与修订，不扫描软件数据库。
2. 应用操作用其只读工具核对名称与当前运行契约；本机操作使用环境与文件只读接口核对必要范围。领域调用方式从该应用的技能获取，不把某个应用的规则套给其他应用；不要重新进行已完成的配置。只缺必要目标信息才用 `user.ask` 一次问清，不为命名或可观测事实提问。
3. 用户给定名称照用；否则沿用用户语言自拟 ≤20 字符的自然短名，不拼目录、作者、时间戳或品牌。用途只描述绑定动作。
4. 单个或原生批量动作放入 `binding.action`；有先后顺序或等待间隔时，按请求顺序用 `binding.steps` 组合为一个入口，不强行合并为批量动作。工具步骤写 `title`、`action` 和可选的只读 `prepare`；固定等待步骤写 `title`、`waitSeconds`（1–86400 秒），不写 `action` 或准备调用。前一步确实完成后再进入等待和后续步骤；启动回执不能当作完成，按所属工具契约使用等待完成或核验能力。通用本机操作可绑定工具目录已提供的文件、命令等能力，不只限于应用插件；保存入口仍不执行这些操作。每个动作使用当前工具目录中的 canonical 工具名和稳定目标参数，严格保持契约的参数层级。不存历史 Job、页面对象、一次性请求标识或整段对话；具体应用的入口与示例留在其领域技能中。
5. 调用 `shortcut.save`：name、description、binding.applicationName、binding.targetName 和具体绑定。更新时带原 id，不另建副本。普通对话里成功即已保存；封装表单只生成预览，由用户确认保存，不能把预览说成已保存。错误按其明确的参数或契约问题纠正，不更换存储通道绕过。
6. 成功后用入口名称说明已加入快捷任务并结束，不再读取文件或试跑；仅点击运行时才执行已保存动作。预览未保存就说等待保存，不说已创建；失败先修正自己填错的参数，仍无法保存时说明具体哪个入口没保存及已查明的原因，不把绑定、契约或内部校验术语当作答复。

边界：保存阶段只读取必要目标信息、提问和保存入口，不执行被封装的修改、删除或启动操作。用户明确要求的新建资源可以作为运行时动作保存；不能为弥补找不到的既有目标而擅自新造配置或替换项目。实际运行仍受通用权限、参数校验、取消和结果核验约束。
