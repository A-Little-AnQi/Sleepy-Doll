# 创建定时任务

用户要求为已有快捷任务设置执行时间时使用此入口。具体操作由定时任务插件的 `schedule-task` 说明管理，不在此入口另写一套执行流程。

1. 用 `skills.search` 核对 `schedule-task` 是否可用；找到后用 `skills.read` 读取，按其对话流程和接口契约执行。用户明确要求新建定时安排时，接通所需定时任务插件属于该目标的必要步骤，可经当前可用且授权的插件管理能力启用；用户明确要求保持停用时不自行推翻，仅查询时也不启用。没有管理能力或启用失败才说明具体阻碍，不通过终端、文件或数据库绕过插件。
2. 计划绑定已保存、已发布的快捷任务。先查实际任务；没有适合入口或现有绑定不适配时，按“创建快捷任务”规则，在用户目标内先只读定位、校验并保存或修复封装，再返回安排。已有入口保留真实身份与修订，不新造业务配置、不试跑，不把手动入口当成定时任务交付。沿用用户已明确的目标、时间、频率和执行顺序；只缺必要信息时用 `user.ask` 合并问清，不重复询问可查询的内容。
3. 创建前按插件规则核对本机时间、预览和真实任务引用。只有实际注册成功才说明已创建；计划、预览或未知结果不代表完成，不在创建过程中试跑任务。

已有入口不可准入时，先按插件 repair 指引查找稳定参数、执行时数据选择与受控组合能力；入口的限制不是用户目标不可实现的证明。未核对可行替代路径前不作绝对不支持结论；也不把仅能手动运行的中间入口当成定时交付。
