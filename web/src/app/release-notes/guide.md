# 使用说明

Sleepy Doll （发条枢）是给游戏助手赋能的 AI 工具，不同于开发者使用的本地 Agent，本工具主要面向于普通用户。

## 快速上手

以当前支持的 BetterGI 为例

### 第 1 步 添加模型

1. 点左下角「本地用户」->「设置」->「模型」。
2. 点击「添加模型」，选择服务商，填写「名称」「请求协议」「API 地址」和 API Key。此处的操作可参照模型供应商提供的 api 文档。
3. 保存，回到「新建对话」，在输入框右下角选择你设置的模型。

不确定通没通？先发一条不用工具的消息：

> 不调用工具，请只回复「连接正常」。

收到回复，便表示已经成功配置好了模型，但是，实际表现仍会因为模型的能力有所差异哦。

### 第 2 步 连接你的第一个工具

1. 启动要接入的工具（打开BetterGI）。
2. 点击侧栏的「BetterGI」，或「设置」 -> 「BetterGI」。
3. 点击「连接」，等待显示「已连接」。

你也可以打开对应工具的自动启动选项，在打开 Sleepy Doll 时自动启动对应工具软件。

通用说明与支持列表见[连接游戏工具](#连接游戏工具)。侧栏里找不到入口？先去「工具与扩展」 -> 「插件」确认对应插件开着。

### 第 3 步 跑通第一次查询

先别急着让它干活，来一次只读查询练手：

1. 把输入框左侧的**审批级别**切到「只读」。
2. 发一句：

> 列出我现有的调度器配置组名称，不运行任务，也不修改任何内容。

3. 等待结果。返回空列表也是正常的（说明你确实没配置组）。

查询没问题了，就可以提出真正的操作要求了。
建议把操作对象和目标描述清楚，例如配置组的完整名称、要改成什么值；描述太模糊时，Sleepy Doll 会主动向你询问。

需要修改东西时需要更换审批级别，出现「确认执行」卡片时请核对对象和参数，选「允许执行」或「拒绝执行」。

## 对话与任务

### 审批级别

为防止小白用户使用时出现数据损坏，特此设立了开发人员才会用到的几个级别，当你熟悉了操作后可以选择性的开启最高级别

| 级别 | 行为 | 什么时候用 |
| --- | --- | --- |
| 只读 | 只查询信息，不做任何修改 | 第一次尝试、核对信息 |
| 请求审批 | 每次修改前弹出「确认执行」询问你 | 日常使用（默认） |
| 完全控制 | 不再逐次询问 | 你已充分了解该任务会做什么 |

### 确认执行卡片

当出现需要卡片上会显示要操作的对象和参数，可展开查看完整参数。点「拒绝执行」后，Sleepy Doll 会调整方案或向你询问意图。切换页面或切换对话不会取消等待中的确认。

### 执行计划与时间线

模型先给出完整计划，程序校验通过后逐步执行。回复上方的「用时」行可以展开查看执行详情：每一步调用了什么工具、传入了什么参数、返回了什么结果。

「部分完成」表示任务执行完毕但缺少验证证据，不代表目标已经达成；确认任务是否真正完成，请查看时间线中的验证记录。

### 上下文进度环

输入框右下角的圆环表示**模型上下文的占用情况**，悬停可查看已用量与总量，它不代表账户余额或费用。完整对话记录始终保存在本机。

## 连接游戏工具

Sleepy Doll 通过接入外部工具来驱动它们；连接之后，就可以在对话里用自然语言下达目标。

**当前支持**：

| 工具 | 说明 |
| --- | --- |
| BetterGI | 原神自动化：查询状态、读取与修改配置、运行任务 |

连接后可在「接口目录」查看当前工具提供的操作，包括用途、参数与副作用。工具重启过后，回去点击一下「重新连接」即可，地址和凭据都是自动配置的。

> 支持列表会持续增加。想接入的工具不在列表里？欢迎反馈。

## 技能与插件

- **技能**：按需加载的操作说明。自己放进数据文件夹的技能可以逐个开关；插件附带的技能随插件一起启用和停用。
- **插件**：可以添加 HTTP 工具和 MCP 子进程。放入目录只是安装，还需要启用才会生效；更新插件前请先停用它。

> 插件声明的「只读」会被当作可信信息，只读工具不会再经过你确认。**请勿安装来源不明的插件**，否则等于允许它在不询问的情况下执行操作。

## 快捷任务

- 在对话里输入「创建快捷任务」并描述目标（或点输入框左下角的 + 选择该技能），AI 会在当前对话里定位已有项并保存成一键入口；入口出现在「快捷任务」页和右侧任务栏。
- 只有成功完成、且具备可复用执行计划的任务才有「保存为快捷任务」入口；纯问答和未完成的任务不会出现这个按钮。
- 再次运行前，建议先查看任务卡片的状态：若提示需要连接工具或补充信息，请先处理；工具未连接时任务无法运行，属于正常提示。
- 在「快捷任务 -> 运行记录」查看每次执行的结果。

## 任务控制

| 你想做什么 | 怎么做 |
| --- | --- |
| 给当前任务补充要求 | 直接发送补充说明，当前步骤结束后处理 |
| 停止当前任务 | 点击输入框右侧的「停止任务」 |
| 停止所有任务 | **Ctrl+Alt+Q**，或右键托盘图标 ->「停止所有任务」 |

- 点击停止后会先显示「正在停止」：程序需要等待当前操作响应停止请求，请以最终状态为准。
- **停止不会撤销已经完成的操作**，已写入的配置、已删除的文件、已完成的操作都会保留。如果游戏或脚本仍在运行，请在对应工具中也执行停止。
- Ctrl+Alt+Q 没有反应时，可使用对话中的「停止任务」或托盘菜单。热键被其他程序占用时会注册失败，原因会记录在启动日志中。

## 托盘与窗口

| 操作 | 结果 |
| --- | --- |
| 点击窗口 ✕（托盘开启时） | 收起到托盘，任务继续运行 |
| 右键托盘 -> 退出 | 结束程序；有任务运行时显示「停止任务并退出」 |
| 在设置中关闭托盘 | 点击 ✕ 直接退出程序 |
| 托盘菜单「打开数据文件夹」 | 直接打开 `user` 目录 |

## 数据、备份与隐私

- **数据位置**：默认保存在程序目录的 `user` 文件夹。实际路径可在「设置 -> 通用 -> 配置文件」查看，自定义过启动路径时以那里显示的为准。
- **备份与迁移**：先退出 Sleepy Doll，再完整复制 `user` 文件夹。覆盖升级不会改动它；卸载时默认保留，勾选「删除用户数据」后才会一并删除。
- **API Key 以明文保存**在 `config.json` 中。长期使用建议改用 `${ENV:...}` 环境变量引用。**请勿将完整的 `config.json` 发给任何人**，分享截图和日志前，请先遮去 Key 与 token。
- **调用在线模型时数据会发送出去**：对话内容和所需的工具结果会发送到你配置的 API 地址；数据保存在本机，不等于模型请求不外发。

## 故障排查

| 现象 | 先试这个 |
| --- | --- |
| 发不出消息 / 模型没有回复 | 输入框是否提示添加模型？按报错核对 API Key、协议、地址与「模型」标识；先发送一条不调用工具的短消息测试 |
| 连接后一直「未连接」 | 工具是否已启动？管理员权限是否授予？点击「连接」查看具体报错；开了多个实例时只保留一个；到「工具与扩展 -> 插件」确认对应插件已启用 |
| 卡在「等待确认操作」 | 回到来源对话，处理「确认执行」卡片 |
| 卡在「等待补充信息」 | 在原对话中直接回答 |
| 点击停止后仍在运行 | 等待「正在停止」结束；在接入的工具中也执行停止；已完成的操作不会回滚 |
| Ctrl+Alt+Q 失灵 | 使用「停止任务」或托盘菜单；热键被占用的记录在启动日志中 |
| 升级后配置异常 | 到「设置 -> BetterGI -> 恢复记录」选择一个备份恢复 |

仍然无法解决时，反馈请提供：双方的版本号、问题发生前的操作步骤、界面错误信息，以及期望结果和实际结果。界面问题可附截图；执行或连接问题可附数据文件夹 `log` 中对应时间的日志片段。无需提供整个数据目录、完整对话记录或 API Key。
