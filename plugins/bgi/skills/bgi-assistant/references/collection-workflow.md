# 资源收集的端到端工作流

“收集一下清心”“帮我刷水晶块”“跑晶蝶”都是直接执行请求。Agent 要自行更新仓库、选择仓库树中的完整路线包、处理订阅和配置，然后运行这个父节点下的全部路线。不要把单个 JSON 路线当作默认执行单位，也不要向用户询问执行几条。

本流程针对已有路线或脚本能够覆盖的材料、敌人和资源，不代表 BetterGI 能自动探索未知目标。“自动找宝箱”“自动收集神瞳”和“自动完成剧情”属于 [capability-boundaries.md](capability-boundaries.md) 中已知不存在的完整功能，应直接说明没有，不进入仓库或能力搜索。用户已经提供点位、录制数据或半成品路线时，才可以按制作请求评估整理与接入。

## 仓库树的执行单位

地图追踪仓库通常是 `pathing / 分类 / 目标 / 作者包或路线文件`。执行单位按树结构判断：

1. 如果目标目录的直接子节点就是路线文件，例如“清心”目录下直接放着多条清心路线，则运行“清心”这个目标目录，交给 BetterGI 递归执行其下全部路线。
2. 如果目标目录下有 `目标@作者`、`目标[变体]@作者` 等作者包，例如“水晶块”下有多个作者目录，则每个作者包都是一个完整候选。选择其中一个作者包，运行这个目录下的全部路线，不继续下钻挑选单条路线。
3. 作者包内部即使还有地区、稳定版等子目录，也保持以作者包为整体执行；具体递归和顺序交给 BetterGI 的目录运行逻辑。只有用户明确点名某个子包或某条路线时，才缩小执行范围。
4. 不要统计路线数量来替用户决定“执行几条”，也不要因为某个叶子文件看起来更短就单独运行。作者已经通过父节点组织好一整套路线。

订阅、加入配置组和运行时都尽量使用同一个父节点路径，避免把作者包展开成许多独立任务。

## 1. 找到目标节点

从用户原话调用一次 `bgi.user.resolve`。它会匹配配置组并核验引用路径，只按目录名定位 AutoPathing 父节点，不会打开叶子 JSON。

- `run`：目标已可执行，进入第 4 步。
- `repair`：配置组还在但路径缺失，只补 `missing`，补齐之前不要运行。
- `create`：本地已有父节点，用它建组；不要读取每条路线的 `info`。
- `notFound`：再检查仓库是否需要更新；更新后再次 `resolve`。
- 不要先搜索单个 JSON 文件，也不要把作者包展开成许多独立任务。

## 2. 多作者自动选择

有多个作者包时由 Agent 自动比较，不把作者列表原样丢给用户。综合作者包及其子路线的 README、描述、标签、更新时间、BGI 最低版本、稳定性标记、是否全收集、是否需要战斗、队伍要求和当前配置，选择与用户目标最匹配的一整包。

如果候选涉及纳西妲（草神）或钟离等明确角色要求，而当前会话尚未确认用户是否拥有对应角色，应先用一句话询问。例如：“这几套水晶块路线分为钟离版和大剑版，你有钟离吗？”得到答案后在本次及后续会话中复用，不要对同一角色反复询问。

若存在效果相当且不需要特殊角色的作者包，可以直接选该包；但不能静默假定用户拥有草神、钟离或其他硬性角色。普通的行走位、生存位和队伍名称优先从现有 BGI 配置中取得，只有硬性条件无法确认时才问。

不要把“作者不同”误解成要混合多位作者的路线。默认只选一个最合适的完整作者包，以免路线重复。只有 README 明确说明不同作者包互补，或用户要求全覆盖时，才组合多个父节点。

## 3. 阅读与配置

`bgi.user.resolve` 已经给出父节点和直接子目录名。不要再核对「所有子路线的 info」或沿途 README，除非 `verdict=create` 且子目录名表明存在互斥的硬性角色要求（例如钟离版/大剑版）而会话里还没有这个事实。

配置取值按以下优先级决定：用户本次明确要求 → 用户已经确认的角色信息 → 现有 BGI 全局设置与配置组 → 当前游戏/BGI 状态 → 安全的官方默认值。只在硬性条件无法确认时询问，不询问路线数量、文件名、目录路径或内部参数。

需要订阅作者包、加入调度器配置组、设置队伍、行走位、生存位、战斗策略、拾取、小道具或其他路线参数时，由 Agent 完成。优先使用已有合适配置组；没有时建立 Agent 管理的配置，避免覆盖用户手工维护的内容。

## 4. 运行与验证

启动所选父节点，确保 BetterGI 接收到的是目录级任务并会递归运行其下路线。打开地图追踪页面、订阅成功或把节点加入配置组都只是准备完成，不是用户目标完成；继续执行到任务真正进入运行状态。

面向用户只需说明所选作者包、关键角色/队伍和已经开始。例如：“已经选了白白喵的甜甜花路线包，下面的路线会按整组依次运行。”不讨论挑了几条，也不列出全部 JSON 文件。

若所选作者包在启动前被证明确实不兼容，可以换另一个完整作者包。任务已经运行并产生进度后，不自动切换到另一个作者包重复采集，除非用户要求或能确认前一个任务没有产生结果。

## JavaScript 收集脚本

只有当用户目标本身需要库存统计、材料 CD、长期补货、复杂前置流程，或仓库没有适合的路线包时，才优先选择 JavaScript 收集脚本。此时读取 `manifest.json`、`settings.json`、README 和必要源码，自行订阅、配置并运行；普通的一次性材料采集优先使用完整地图追踪父节点。
