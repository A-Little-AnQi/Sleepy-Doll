# ViewModel 与页面能力的使用规则

ViewModel 中确实存在用户可用能力，不能一概隐藏。应按实际效果分类，而不是按类名决定是否能被 Agent 使用。

## 可以进入普通能力目录

- 打开或切换到明确的 BetterGI 页面、窗口和设置区；
- 刷新页面数据、选择用户可见项目或打开脚本仓库；
- 与页面按钮等价、行为边界清楚且能够返回结果的命令；
- 在没有更稳定领域服务时，用于读取或修改一个明确用户设置的属性。

常见用户页面包括启动页、一条龙、调度器/配置组、地图追踪、JavaScript 脚本列表、自动战斗、实时任务、快捷键和通用设置。能力标题应使用这些页面名称，不出现 `HomePageViewModel`、`ScriptControlViewModel` 等类名。

## 默认隐藏或仅开发可见

- `OnNavigatedTo`、`OnNavigatedFrom`、`Dispose`、构造函数和生命周期钩子；
- 纯粹为绑定、通知、缓存或 UI 状态服务的属性；
- 返回窗口对象、控件、命令对象、DI 服务或不可序列化对象的方法；
- 任意属性写入、任意命令执行和没有业务含义的反射入口；
- 已有领域服务或高层任务覆盖的内部实现。

## 选择优先级

用户要求完成实际任务时，优先级是：完整任务/脚本/路线 → 明确领域操作 → 有相同业务效果的 ViewModel 命令 → 页面内低层操作。用户要求“打开地图追踪页面”时，页面导航本身就是目标，可以直接使用 ViewModel 或导航服务。

页面打开成功不能证明脚本已配置或任务已运行。若用户要求“帮我跑路线”，可以打开页面作为可视反馈，但仍要继续完成选择、配置和启动。

对于 ViewModel 上的配置属性，先读取当前值，只改用户目标所需字段，并用保存结果或再次读取确认生效。若直接操作属性不会触发校验、持久化或联动逻辑，应改用对应命令或领域能力。

## 能力元数据建议

ViewModel 派生能力应增加 `surface_role`：`navigation`、`ui_command`、`config`、`task` 或 `internal`；再增加 `completes_goal` 表示它是否真正完成用户目标。搜索排序中，`navigation` 不应在“收集、刷取、运行”请求中排在 `task` 前面，但应在“打开、带我去、显示”请求中优先。

普通回复始终说页面或功能名称。例如说“已经打开地图追踪页面”，不要说“已调用 MapPathingViewModel 的导航方法”。
