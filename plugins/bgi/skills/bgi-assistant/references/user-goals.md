# 日常用户目标图（按功能域）

普通用户用口语提目标，不给脚本名、字段或接口。本页把口语映射到：原生功能／仓库现成脚本／需要新开发，并写清配置作用域、哪些事实程序自取、哪些必须问用户、结果算不算完成、常见误解。脚本与地区结论来自脚本仓库实测阅读（manifest/README/settings/main.js），不是游戏实跑；运行成功与否以现场任务结果为准。

处理用户一句话时的通用顺序：先用 context 把"那个/后面那个/别动"归一到具体资源（历史已证实的 name/path 优先）。参数尽量程序自取：历史值、已配置值、仓库 README/settings 里的现成字段、可靠默认；已有配置就不问数量/队伍/地区（"跑清心""运行那条现成路线"直接执行）。只有业务确实缺且不可推断的人类目标才问，且一次问清：典型如明确"换个队"却没说换成哪个——注意背包/角色名单不是队伍名；"跑完通知我"需要用户指定渠道和接收范围，不因设置里存在某字段就反过来问用户。归一后的发现入口按目标性质选择：本机资源走 bgi.user.resolve，仓库现成脚本走 bgi.repo.search，不确定对象走 bgi.feature.search 与功能索引——口语目标不要求全部命中索引，解释类问题不做动作搜索。普通回复只讲目标、结果和必要缺项，不暴露英文实现名和逐步探索过程。仓库脚本 settingsUi 可能缺文件或字段不同名，以现场 manifest 和读到的 settings 为准。

## 启动、截图与后台环境
- 口语："把原神开了""截个图看看现在画面""后台挂着别动我屏幕"。
- 原生：启动页（联动启动、截图方式、分辨率、触发器、多开窗口）；`bgi.start_game`、`bgi.get_status`、截图接口。管理员权限与安全软件是常见失败原因。
- 证据：进程/窗口句柄、主界面可截图；启动成功不等于后续脚本会成功。
- 误解：BGI 不需要"进游戏后手动开启"；多数功能要求已连接到游戏窗口。

## 实时拾取、剧情、邀约、回血
- 口语："帮我捡东西""对话自动点""邀约帮我跑""别让角色躺着死"。
- 原生实时任务：自动拾取（黑白名单、拾取键）、自动剧情/自动邀约（选项优先级）、凯瑟琳相关、自动吃药回血、技能冷却提示。独立任务运行期间实时任务会暂停——用户报"怎么不捡了"先解释这一点。
- 边界：实时"自动剧情"只是自动点击/跳过当前剧情，不等于替用户做完某个任务剧情；完整任务剧情需要任务脚本支持（见"剧情与宝箱"域）。
- 作用域：实时任务开关属全局设置。

## 游戏动作键、BGI 热键与宏
- 口语："按 E 没反应""把连招绑个键""宏帮我录个挖矿"。
- 区分三层：游戏内按键绑定（KeyBindings）、BGI 全局热键（HotKey，可能与其他软件冲突）、宏/连招（Macro 配置与键鼠脚本）。
- "识别到了却不按键"先归到输入权限；"按键不对"先分清是游戏键位还是 BGI 热键。

## 调度器、路线组、配队策略与运行顺序
- 口语："把这几个串起来跑""先锄地再挖矿""那个组里加个收尾"。
- 原生：调度器配置组（JS、地图追踪、键鼠脚本排序、启停、从指定位置继续、组通用配置）。地图追踪组内可配切队、战斗策略、拾取、恢复等运行参数——现成路线换队优先改组配置（`bgi.prepare_pathing_group` 复用/包装），不写切队 JS。
- 顺序与开关是组编辑；"全局设置"是另一回事，不把全局开关吞进组编辑。
- 证据：组回读（名称、条目、顺序、关键参数、sha256）；"已保存"不等于"已跑通"。

## 换队：三个不同的动作
- 口语都是"换个队"，实际分三种：
  1. 切换到已保存的配队（`genshin.switchParty` / 组配置切队）：需要用户已保存同名队伍；目标队名缺失必须早问，不可推断。
  2. 配对界面逐位换角色（仓库脚本 AutoSwitchRoles）：按位置填角色，支持别名，可指定队伍；联机时切换会失败。
  3. 战斗策略按名单识别（AutoFight 的 teamNames 一类配置）：不是切队，是战斗脚本认哪些队。
- 用户说"用我那个收割队"：先在本机配置/历史证据里定位真实队名，找不到再问；不要让用户填字段名。

## JS 参数与现成脚本
- 口语："这个脚本怎么配""那个选项啥意思""改下次数"。
- 每个仓库脚本：manifest（名/版本/settings_ui/main）、README（前提/限制）、settings.json（真实参数）。settings_ui 可能缺失或与文档不同名。
- 改参数=写脚本自身 settings 或组内 JS 自定义设置；不改源码、不造等价 JS。库存/CD/复杂完整流程优先复用已有 JS。

## 键鼠录制回放
- 口语："录一下我手动跑的这条路""回放刚才那段操作"。
- 原生键鼠脚本录制/编辑器；可放进配置组参与编排。录制产物是用户操作的重放，对分辨率/时机敏感，失败先看日志回放段。

## 原生日常一条龙
- 口语："每天自动做完日常""一条龙跑一下"。
- 原生一条龙默认任务严格为 8 项（OneDragonFlowViewModel 的 _scriptGroupsdefault）：领取邮件、合成树脂、自动秘境、自动首领讨伐、自动幽境危战、自动地脉花、领取每日奖励、领取尘歌壶奖励。每日委托、锻造、七圣召唤等不在原生默认列表；相关能力通过把社区 JS 脚本组加入一条龙的配置组扩展。支持多套配置、从某项继续、完成后操作。
- "领取邮件"（ClaimMailRewardsTask）和"领取每日奖励"是两个独立任务。"领取每日奖励"页面标题是 DailyRewardViewModel，真实实现（Model/OneDragonTaskItem.cs）依次调用 GoToAdventurersGuildTask——前往凯瑟琳/冒险家协会：领取历练点奖励、每日委托领奖、继续派遣——和 ClaimBattlePassRewardsTask 领取纪行奖励。它是领奖动作，不等于替你完成四个每日委托；委托完成要靠自动委托脚本且有地区限制。
- 树脂使用、脆弱/须臾树脂、完成后关机等高影响选项必须用户明确；`bgi.run_one_dragon`。
- 证据：一条龙任务列表与各任务完成状态；"启动了"不等于"全部做完"。

## 战斗、首领、秘境、地脉与树脂
- 口语："把体力清了""刷三次数秘境""今天周本打了""地脉花刷完"。
- 原生独立任务：自动战斗、自动秘境（副本/树脂/队伍）、自动首领讨伐、自动地脉花。仓库增强版：AutoDomainCustomizable（树脂顺序、轮数、闲时刷圣遗物、结束分解）、AutoLeyLineOutcrop（树脂耗尽模式、20树脂模式、双倍、国家路线不完整仅测试）、首领连续讨伐（选首领、次数、树脂、键鼠路线依赖钟离行走位）、WeeklyBoss 周本一条龙（部分周本要自录键鼠、料理限制、复活检测）。
- 树脂策略（浓缩/原粹/须臾/脆弱的顺序与数量）是消耗性选择，只按用户明确范围执行，不因脚本默认扩大。
- 证据：次数、奖励领取与树脂消耗的任务结果；战斗失败/超时如实报。

## 钓鱼、伐木、烹饪
- 口语："把鱼钓了""木头砍到上限""做饭/加工食材"。
- 原生独立任务：自动钓鱼（GameTask/AutoFishing 的 AutoFishingTask 与实时 AutoFishingTrigger，针对当前位置抛竿垂钓）、自动伐木（GameTask/AutoWood 的 AutoWoodTask）。原生任务是"在当前点位执行"，跨地图逐点跑完整流程靠社区脚本。
- 仓库社区流程：AutoFishingTeyvat（地区/鱼/饵筛选、CD 记录、鹤观羽毛、战斗路线需配策略）、自动伐木-地图追踪版（木材种类、数量、王树瑞佑、一斗保底）、一只爱可菲（自动烹饪/熟练度/特殊料理/食材加工，分辨率敏感需调时延）。
- 前提是用户实际可满足的（羽毛道具、装备、材料）；缺失时如实说明，不硬跑。

## 圣遗物：锁定、强化、分解、销毁
- 口语："垃圾圣遗物处理了""强化到20""狗粮换了摩拉"。
- 仓库：AutoArtifactsSalvageOrDestroy（1-4星分档，分解/摧毁二选一，摧毁一次上限100）、DestroyArtifactsForMora（摧毁换摩拉、前后摩拉对比）、HolyRelicsUp（批量强化：强化等级/个数/排序/套装筛选，界面识别对语言敏感）、AutoBackpackCleaner（爆仓材料删到目标数量，仅0-2星材料和养成道具页，白名单保留）。
- 分解、销毁、删除是不可逆消耗动作：只落实用户明确的星级/范围，绝不按脚本默认全选扩大；执行前把范围说清。
- 误解：原生"圣遗物分解"独立任务与上述脚本范围不同，别混用。

## 七圣召唤与音乐
- 口语："打牌周常做了""牌组熟练度刷下""放首曲子"。
- 原生：七圣召唤对局自动化（GameTask/AutoGeniusInvokation 的 AutoGeniusInvokationTask，按策略打当前牌局）、音乐页/曲谱播放（MusicConfig）。
- 仓库社区流程：打牌一条龙（七日历练/来客挑战跨地图找对手，牌组名、备用策略、云端统计需知情）、七圣召唤角色邀请（需邀请函或牌币）、TCGQuickProficiency（联机双账号投降刷熟练度，有账号风险须告知）、DSTCG 智能打牌（手牌逻辑未完善）。
- 牌组名是意图值：用户没给且无法定位时早问。

## 仓库：订阅、更新、本地缺项
- 口语："把那个脚本装上""路线更新下""说没有的东西装了吗"。
- 原生脚本仓库页与 `bgi.subscribe_script_resources`；订阅后地图追踪/JS 落到本机 User 目录。"本机没有"不代表仓库没有，先查中央仓库；更新可设启动时自动更新已订阅脚本。
- 订阅范围只按用户目标的最小集合，不顺手全订。

## 背包统计、目标库存与 CD 采集
- 口语："看看我还缺多少甜甜花""矿够不够""把 CD 好的材料采了"。
- 仓库：背包材料统计/背包统计采集系统（统计+按目标数量与材料 CD 自动跑路径，需自备 pathing 目录）、采集cd管理（按组循环、CD 跳过、优先材料）、CD-Aware-AutoGather（同步订阅的地图追踪、目标数量、联机多账号记录、自动切队）、AbundantOre（矿石 CD 记录、按区域/种类/数量/时长终止、队伍需莉奈娅或诺艾尔）、LinneaMining（莉奈娅挖矿，仅挪德卡莱）。
- 关键纠正：这些脚本的"CD"是运行时筛选与记录，不是跨天计划任务；BGI 不会自己第二天唤醒。用户说"以后每天自动"要落到一条龙/配置组或说明需要外部触发。
- 需要用户选择：目标数量、优先材料、队伍；地区/矿种可筛选。

## 尘歌壶、商店、锻造、兑换码、领奖
- 口语："洞天宝钱领一下""商店买树脂""铁匠铺锻造""兑换码用了""月卡/邮件领了"。
- 仓库：尘歌壶一条龙（阿圆路径、购买、锻造、做饭，星期可选）、自动购买商品（按地区/商品、刷新周期、背包上限处理）、铁匠铺自动锻造魔矿（每日限额识别）、AutoCode 兑换码（仅国服，公共码+BGI 列表）、每月自动兑换抽卡资源（星尘换蓝粉球）、自动月卡、自动领取成就奖励、无树脂每日领奖（凯瑟琳领奖+派遣+纪行+尘歌壶）。
- 尘歌壶路线、脚本目录布局等准备由 Agent 从现成可用资源完成（先查脚本自带与已订阅数据），无可靠路径如实说明；购买清单是消耗性意图：只买用户点名的物品，不用脚本默认清单扩大。
- 兑换码有截止时间与服务器限制（国服）。

## 角色养成
- 口语："把这个角色练到 90""天赋 6/6/6 拉一下""天赋材料刷够"。
- 用户只给人类目标（角色、等级/技能目标、是否刷材料）。材料总量能从可靠养成计划或当前角色数据计算时程序自行算好并填进脚本参数，不让用户手算米游社数字；缺当前等级/目标或没有可靠计划来源时，才简短问对应的业务事实。
- 明确范围：仓库的角色养成一条龙只刷材料到指定数量——不升级角色、不合成材料、不采区域特产和怪物材料，不承诺"一键全养成"；README 警告刷取中途打断会数量失真。
- 脚本所需的数据准备（pathing 目录布局、切队配置等）由 Agent 查现成可用资源并完成；CD-Aware 类脚本直接扫描已订阅的地图追踪目录，优先于要求手工摆放 pathing 文件夹的方案（用户明确点名某脚本时尊重原目标）。没有可靠路径时如实说明缺口，不乱造路线，也不把作者"你自己复制目录"的教程原样退给用户。
- AutoPlan 自动体力计划：计划内容或配置来源是用户的人类选择，需用户给；循环到体力尽、复活重试等按其配置。

## 日志、排障、停止与恢复
- 口语："卡住了""又失败了""停下""刚才改的设置撤回"。
- 原生：任务日志与日志分析、`bgi.job.cancel`/`bgi.stop_current_task`、设置恢复（preview+commit，可回退）。
- 停止区分：等待中 Job 用 cancel；已交接的启动 Job 已终态用 stop_current_task 并核对原目标。排障先读真实错误，不猜。

## 通知与收尾退出
- 口语："跑完发个 QQ""跑完了把游戏关了""收尾关掉"。
- 原生通知系统（Webhook/QQ/微信绑定、测试发送）；事件订阅是全局作用域（NotificationEventSubscriptionHelper：空订阅=所有事件放行），配置组没有 per-group 通知字段；组/一条龙完成后操作；多组收尾统一 run_script_groups(closeGameAfter)，后台交接只承诺"已提交计划"，不承诺即时完成。
- 已绑定的渠道与订阅自读即可，不重复问；不擅自增加无关渠道、不把订阅扩成全部事件、不外发截图或自动测试内容。
- 关键纠正："收尾关掉"必须区分：退原神（原生退出游戏/ExitGameMultipleMode 的 Alt+F4/完全退出）不等于关电脑。计算机电源操作脚本会注销/睡眠/关机/重启（默认注销）——绝不在用户只说"关游戏"时使用电源脚本；"关电脑"也要确认方式。
- 外发通知只发用户指定的渠道与内容。

## 远程分身与电脑电源
- 口语："我在外面用手机看""挂完机把电脑睡"。
- 原生桌面分身/子会话（远程查看）；电源动作只经计算机电源操作脚本且用户明确（注销/睡眠/休眠/关机/重启）。账号切换（SwitchAccountMultipleMode）涉及账号密码本地保存与人机验证风险，只按明确指示执行。

## 剧情、邀约任务与宝箱
- 口语："主线剧情帮我过了""邀约做了""刷宝箱"。
- 边界：实时自动剧情/点击只是跳过当前播放。剧情加载器（AutoStoryLoader 类）只加载已有流程文件，工具本身不含任何任务流程；"能加载"不证明某条主线有可执行流程。仓库与本机没有对应流程时，如实说明当前缺少可执行内容，不宣称支持，也不为规避否定编造流程或"私群脚本"来源。不能一刀切说"主线任何时候都不能自动"，要说清当前有什么真实可用。
- 仓库 README 的免责确认、使用条款是资料背景，不是产品授权门槛，不作为 Agent 执行的前置审批。
- 宝箱类：先按目标关键词检索本机与当前仓库的特定范围实现（如 AIPC珍贵宝箱无限刷 这类特定点位循环脚本），命中后核对其 README、参数与关键源码条件，按真实点位范围回答；不凭"没听说过"断言不存在，也不从一个脚本的特定点位宣称全地图自主探索。确认无现成数据才说明缺口。

## 版本、来源与能力边界
- 口语："我这个版本能用吗""这个结论哪来的"。
- 原生 docs/bgi/feature-coverage.json 与 Native HEAD 对齐（命令/设置/页面/脚本方法等静态覆盖），但静态存在不等于游戏实测成功；仓库脚本结论来自代码与 README 阅读，保留国家/地区/版本/角色与消耗条件。
- 回复中的能力承诺按当前契约（`bgi.api.describe`）与实际运行结果，不按数量宣传。
