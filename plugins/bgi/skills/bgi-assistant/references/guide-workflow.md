# BetterGI 全功能问答与操作流程

本技能必须能处理 BetterGI 的普通使用问题，而不只会运行路线。用户可以询问任意页面、开关、任务、配置组、一条龙、脚本、仓库、快捷键、通知或运行方式。

## 先操作还是先指导

1. 用户明确要求“打开、设置、运行、停止、更新、收集”时，优先直接完成；只有页面本身是目标或直接接口确实不适用时才导航。不要先讲一遍教程再动手。
2. 用户问“怎么设置/怎么用/使用教程”时，只给这一问需要的入口和选项。不要先推销代劳，不要把整份功能地图写进回复，也不要在末尾追问下一步想配什么。用户随后明确要求代劳再动手。
3. 直接接口不能完成时核对具体限制；原生界面确能完成且属于用户目标才使用界面。仍无法完成时说明缺口和准确的手动路径，不随意打开相近页面充当进展。
4. 用户只问概念、区别或机制时直接解释，不擅自改设置，不附带未问的功能。

## 知识查询顺序

具体脚本或 JS 字段的问题优先搜索脚本标题，读该脚本的 settings、README 和必要源码，不先查本体设置与用户的一条龙配置。用户用口语描述日常目标（"清体力""垃圾圣遗物处理了""收尾关掉"）时，先用 [user-goals.md](user-goals.md) 选域并对齐取舍，再回本流程取来源。其他问题类别不清楚时用 [feature-map.md](feature-map.md) 确定功能域，并按 [source-routing.md](source-routing.md) 定位路径。feature-map 只供定位，不复述给用户。与现场无关的讲解不要走第 1 步。按问题所属对象选择以下来源：

1. 当前 BGI 状态、配置和 `bgi.api.describe`：判断当前版本真实可用的操作、当前值和参数；仅当答案取决于现场值时使用；
2. `bettergi-docs/src` 官方用户文档：回答界面路径、使用前提、选项含义和常见问题；
3. 当前 BGI 源码中的页面 XAML、ViewModel、配置类和 GameTask：文档缺失或版本落后时核对真实选项与行为；
4. 脚本仓库的 `repo.json`、README、manifest、settings 与源码：用于特定路线、脚本和策略；直接 `bgi.repo.search/read`，未订阅文件也可从中央 Git 仓库读取。问题涉及本机运行时优先读已安装版本；
5. 动态日志与诊断信息：只在排障时按需读取。

不要把源码类名直接当成用户答案。源码确认 `AutoUpdateSubscribedScripts` 后，用户答案应是“可以在脚本仓库设置里开启启动时自动更新已订阅脚本”。问怎么开就说到这儿；用户要你改时再改。

## 配置诊断与运行优化

用户问“还缺什么配置”“怎样运行更稳／更快”时，检查的是现有任务的实际效果。沿用已有目标、启停、队伍、拾取和消耗取舍；只有缺少会改变建议的人类目标时才用 user.ask 问清，不默认追求最高数量或开启全部功能。查看、分析不授权修改配置或启动游戏任务。

- 定位实际启用的任务，读取生效配置及本机脚本版本的 README、参数定义；必要时追踪参数引用、继承覆盖、共享账户与运行顺序。仓库新版本不能代替本机运行版本的证据。
- 先查与目标有关的失败、耗时、重复执行、漏拾取、恢复和切队记录，再判断瓶颈。日志没有记录或只有历史文件时，明确证据不足；不据此宣称能正常执行、自优化有效或收益已经提高。
- 区分已证实的配置错误、需要核实的运行风险与适用条件明确的可选调整。字段缺失须检查默认值和覆盖来源；两个任务选路是否重叠须比较真实选路结果，不能仅凭名称、数量或同账户下结论。
- `genshin.switchParty` 的目标是原神游戏内保存的队伍。BGI 配置里的队名只是切换目标，本机文件搜索未命中不能证明游戏里没有该队。核实依赖已有游戏识别或切队记录；无法观测就说尚未核实，不要求用户在 BGI 里创建游戏队伍。
- 队伍校验名单来自已明确的实际队员，不用文档推荐角色或示例填充。作者建议与当前队伍、策略和拾取目标适配后才可推荐。
- 料理、加速、特殊传送等可选设置，只有解决当前瓶颈且角色、库存或装置条件有依据时才建议；说明相关消耗和收益取舍，不因留空就认定需要补齐。
- 重组任务前核对当前版本的分组语义、路线分配、排除范围及执行顺序，确保保留用户目标。仅源码分析支持的结论不能表述成实际重复执行或游戏验证通过。

答复先说最值得处理的已证实问题及影响，再给必要的待核实项或有依据的建议。用界面选项和用户目标描述；字段、源码分支和探索细节留在过程证据中。比较清楚时可用短列表，不输出整份设置教程，也不追加“需要的话我可以改”。用户明确要求调整后，自己完成已授权的配置与回读；确需用户在游戏内处理的事项才交给用户。

## 文档检索方法

使用用户原话、BetterGI 规范名称和同义词同时搜索。例如“自动点对话”扩展为“自动剧情 自动邀约 选项优先级”；“每天做完”扩展为“一条龙 每日委托 每日奖励 配置组”；“键位不对”要同时区分快捷键与游戏按键绑定。

找到文档后读取包含该问题的完整小节，不只使用搜索片段。若官方文档与当前源码冲突，以用户运行的 BGI 版本为准，并自然说明版本差异。找不到文档时再查对应 XAML、配置类或任务参数，不猜页面名称和默认值。

## 指导操作的写法

指导必须落到用户看得见的入口和选项，例如：“打开「全自动 → 调度器」，选中配置组后点「设置」，这里的单任务配置会覆盖地图追踪全局设置。”不要说“修改 ScriptControlViewModel 的属性”。

步骤较少时用一两句话说完；只有用户要的就是连续操作时才编号。只解释当前问题相关的设置，不倾倒整个页面，不顺带介绍同页其他开关。若某个设置会在下次任务、重启或重新打开页面后生效，要明确指出。

## 能力缺口

“当前 Agent 没暴露”不等于 BetterGI 不支持。先搜索高层任务、配置、页面导航和 ViewModel 命令；若仍无直接能力，查官方文档并指导用户操作。对开发者可以额外说明需要补充暴露的具体能力，但普通用户只需要可执行办法。

## 覆盖检查

回答前确认自己没有把“一条龙”误当成调度器配置组，没有把中央仓库更新误当成订阅更新，没有把实时任务当成独立任务，也没有把打开页面当成完成任务。涉及地图路线时确认执行的是父节点；涉及全局设置时确认修改的是正确配置域并已保存。
