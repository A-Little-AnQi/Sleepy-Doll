# 排查实际失败

从本次失败的对象、输入、日志和版本开始。区分调用错误、资源缺失、前提不足、冲突任务、超时与业务失败，不能凭一个无关状态猜原因。

先修正助手填错的参数、引用和层级，再按当前能力核对现场；新版本接口或对象变化时重新发现，不反复重放旧标识。一个界面命令失败不证明直接数据能力不存在，索引未命中也不证明整个软件没有功能。

未知效果的写入或运行先核实实际状态，不能直接重发。取消与超时不保证副作用已撤销。只有真实必要的人类选择缺失才问，不让用户处理助手的内部参数。

证据不足时明确哪件事未完成及原因仍未查明；不罗列假设、不复述内部检查意见。实际结果与静态分析、隔离测试和游戏验证分开说明。
