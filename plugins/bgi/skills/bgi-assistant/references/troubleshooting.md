# BetterGI 排障知识

先基于当前状态和证据缩小问题，再给最短的下一步。不要一次抛出十几项通用检查。

## 基础运行条件

BetterGI 官方文档当前说明：支持 Windows 10 及以上 64 位系统，需要 .NET Desktop Runtime；游戏语言应为简体中文。推荐 1920×1080，多数功能支持不低于 1080p 的 16:9 分辨率，但具体功能可能不同。默认亮度、不使用 HDR/N 卡/ReShade 等画面滤镜更有利于图像识别；覆盖游戏画面的 FPS 或硬件监控浮层也可能遮挡识别区域。

BetterGI 依赖图像输入。普通本地游戏可尝试 BitBlt、DwmGetDxSharedSurface 或 WindowsGraphicsCapture；PC 云原神需要 WindowsGraphicsCapture，并可能需要手动选择正确窗口。模拟键鼠无效而识别日志正常时，优先检查 BetterGI 是否以管理员身份运行，以及安全软件是否拦截模拟输入。

## 最小诊断顺序

1. 确认失败的是所有功能还是某一个任务；查看当前任务和最近的用户可见错误。
2. 若完全没有识别日志或画面状态，检查游戏窗口、截图方式、遮挡、滤镜、HDR 和分辨率。
3. 若识别到了目标但没有实际按键/点击，检查管理员权限与安全软件拦截。
4. 若只有某个脚本或路线失败，先按下面的「脚本报错」取日志里的一手报错，再检查脚本 README、设置、版本、订阅状态、队伍/角色要求和断点位置。
5. 若独立任务运行时实时功能停止，这是任务调度的正常行为；等独立任务结束或停止它后再验证。

## 常见专项

- 自动拾取：先看是否识别到交互文字。完全没日志偏向截图问题；持续识别但没有按 F 偏向输入权限或拦截。也要检查黑白名单与自定义拾取按键。
- 自动剧情：游戏内自动播放状态和 BetterGI 相关开关会影响行为；凯瑟琳领取/派遣与邀约还有独立选项。
- 地图追踪：官方文档要求自动拾取可用、小地图锁定方向、16:9 且通常至少 1920×1080；还要检查路线版本、队伍名称、所需角色、战斗策略与脚本设置。
- 自动秘境/战斗：检查配队识别、策略与实际队伍匹配、超时、奖励识别和进入秘境后的阶段。不要一看到超时就建议换接口。
- 脚本仓库：首次需更新中央仓库；更新中央仓库不等于更新已订阅脚本。在线订阅仍依赖本地中央仓库中存在相应文件。
- JavaScript 脚本：运行前读取 README 和 settings；失败时按下面的「脚本报错」取一手报错，不把脚本作者实现细节直接倾倒给普通用户。

## 脚本报错

用户说某个脚本、任务或配置组中途失败时，自己去读日志里的一手报错，不要让用户复述过程或贴日志。调用顺序见 `bgi-operator` 技能的「排查脚本报错」。

1. 用 `bgi.get_script_errors` 取报错原文、出错脚本名和涉及的文件位置。日志里没有记录时直说没有，不编造原因。
2. 报错指向脚本自身逻辑时，读 `User\JsScript\<folderName>\main.js` 对照；指向缺失文件时，那是路线、数据或配置文件没装或没更新，按订阅状态处理。
3. 答复只讲结论：哪一步失败、原因是什么、下一步做什么。栈帧、异常转储和脚本作者的实现细节留给用户明确索要技术细节时。
4. 桥版本较旧、没有这个接口时，退回到 BetterGI 调度器页面的「日志分析」，或让用户提供失败时段的日志。

若用户要求更深的技术诊断，再给出原始日志、能力 id 和代码位置，并明确区分“BetterGI 本身支持”与“当前 Agent 没有暴露”。
