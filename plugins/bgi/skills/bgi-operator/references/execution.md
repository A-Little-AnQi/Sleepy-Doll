# 任务准备、运行与停止

从当前任务能力的说明确认它接受什么目标、会消耗什么、是否自动准备游戏，以及返回时代表完成还是仅接纳。不要固定方法名、就绪字段或调用顺序。配置与资源管理通常不依赖游戏就绪，不能为读取设置或封装入口启动游戏。

已有任务沿用保存的启用项与参数。只有本次动作确实需要的前提才检查；若能力已经负责准备和等待，不再由模型拆成多次状态轮询。缺少登录、安装信息、人工验证或遇到冲突时按具体事实处理，不擅自重启、改分辨率或绕过用户拒绝。

多项运行保持用户顺序及收尾要求，优先使用当前软件支持的批量或计划能力。用户未要求等待结果时，选择契约所支持的后台接纳方式；取得真实接纳结果后结束本轮，不继续读取日志、截图或状态。用户要求等结果时，使用任务系统的阻塞等待或事件能力，而不是不断请求模型。

停止的对象应是实际仍在运行的任务。提交请求已结束不代表后台任务已结束；区分取消等待、请求停止和核实停止。不要把超时或取消请求当作已停止，也不重复启动结果未知的任务。

启动、接纳、运行中和完成各有不同证据。查询当前任务、状态、记录或输出后，仅报告所能核实的阶段；报错先修正调用或查具体原因，不把错误接口的失败当作整项用户任务不可能完成。
