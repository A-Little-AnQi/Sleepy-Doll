# 绝区零一条龙 MCP

连接绝区零一条龙提供的 MCP 服务，处理绝区零自动化任务。服务端发布工具定义并执行操作，Sleepy Doll 负责工具发现、用户授权和结果呈现。工具前缀为 `zzz.onedragon.`，下文使用服务端的原始工具名。

## 工具发现

通过 `tools.search` 按当前目标查找工具，以服务端返回的参数定义、应用列表和配置结构为准。按需读取 `list_mcp_usage_guides` / `get_mcp_usage_guide`；应用 ID、操作 ID、角色编号及配置值均从实际结果取得。

## 应用与任务

- 运行状态：`get_run_status` 查询任务，`check_game_window` 检查游戏窗口。服务连接、窗口存在和任务可运行是不同状态。
- 一条龙日常：确认当前没有其他任务后，使用 `run_one_dragon(block=false)` 运行已启用的应用组。需要查看应用及启用情况时调用 `list_applications`。
- 独立应用：从 `list_applications` 取得 app_id，再调用 `run_standalone_app(app_id, block=false)`。沿用已保存配置，执行内容与资源消耗应符合用户要求。
- 单个操作流程：按需使用 `list_operations`、`describe_operation` 和 `run_operation(block=false)`。现有应用能够完成目标时直接运行应用。
- 停止任务：调用 `stop_run`，再通过 `get_run_status` 确认停止结果。stopped=true 表示停止请求已发送。

运行默认采用后台提交。started=true 表示已提交启动请求；实际开始、完成或失败以任务状态和执行结果为准。用户要求等待或跟进时继续查询；普通启动请求交接后结束本轮。已有任务运行时，保留当前任务，未经用户要求不停止或叠加操作。MCP 请求取消与后台任务停止分别核对。

## 配置与编队

使用 `list_app_configs` 查询可管理的配置，通过 `describe_config` 读取字段与取值约束，使用 `get_config` 读取当前内容。修改用户指定的字段或条目后回读确认。

`get_predefined_teams` 提供预备编队查询；编队编辑及其他设置是否可用，以服务实际提供的工具为准。服务未提供的配置能力应明确说明，不能用猜字段、反射或直接改 YAML 代替 MCP 接口。

## 画面与游戏交互

键鼠操作前确认游戏窗口并观察当前画面。点击、拖拽等坐标采用一条龙的 1080p 游戏空间；锁光标场景按工具定义使用 pc_alt。操作后等待画面更新，再观察实际结果。

`analyze_screen` 返回 OCR 与已有模板的识别结果。需要判断完整画面时查看截图；截图路径本身不构成视觉证据。实时战斗使用服务端的自动化流程。画面区域的增删用于识别配置维护，按用户明确要求执行。

## 连接与结果说明

连接失败时，明确说明“无法连接绝区零一条龙 MCP 服务”，根据已取得的连接地址、服务状态和错误定位原因。需要用户启动服务时，给出“一条龙 → 开发工具 → MCP 服务”的入口，或插件附带的启动命令；服务启动后重载 Sleepy Doll 扩展。默认地址为 `http://127.0.0.1:23001/mcp`。连接失败不能据此判断任务、配置或资源不存在。

答复说明操作对象、执行状态和实际结果。日常任务使用用户可见的应用、编队和设置名称；涉及 MCP 连接、工具定义或参数排查时，准确使用相应术语。参数错误先依据当前工具定义修正；执行失败说明已确认的原因和下一步，不照抄整段内部错误。
