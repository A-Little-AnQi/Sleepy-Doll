# 定时任务

本插件管理“什么时候按什么顺序运行哪些快捷任务”。安排的注册和管理只用受限的 `scheduler.*` 接口；目标定位、能力发现及封装校验可使用对应软件的受控只读工具，不通过终端、文件、数据库、Windows 任务管理界面或宿主自建调度绕过注册边界。不把计划、预览、排队或未知结果说成已经完成。

按需用 `skills.reference` 读取本技能的 [对话流程](references/conversation.md) 和 [接口契约](references/api.md)。首次创建或修改前读取两份；查询、启停、删除、立即运行及排错只读相关章节。`tools.search` 取得当前接口声明，文档不能替代当前参数契约。

## 处理流程

1. 区分用户要创建、调整、查询、暂停、恢复、删除、立即执行还是停止本轮。沿用本轮已明确的信息；“改到九点”是在修改已定位安排，不另建一条。
2. 创建时用 `scheduler.actions.list` 按标题或内容查真实任务；管理已有安排用 `scheduler.list`、`scheduler.get` 定位。存在歧义才用 `user.ask`，一次合并必要问题；不问可查询事实、内部参数、例行名称或已经明确的条件。
3. 用 `scheduler.clock` 取得本机日期与时间，再解释“明天”等相对日期。只执行一次必须有具体日期与时分；通过该接口换算本机时间，不猜 UTC 偏移。按天（含每 N 天）、每周、每月使用本机时区与 24 小时时刻。每两天等固定天数循环用 daily.intervalDays 与 startDate，保持起算日期和本地时刻，不改写成星期组合；用户未给起算日时，从下一次该时刻所在日期开始，并在预览与回复中说明。未支持的节假日、按小时循环或跨时区规则不能私自改写。
4. 保留用户给出的执行顺序，允许 A → B → A；每次触发运行整个列表，每项出错后继续尝试下一项。注册时目标必须是已保存、已发布、可定时执行的快捷任务；缺少适合入口或绑定不适配时，先按创建快捷任务规则，在本轮目标范围内保存或修复稳定封装，完成只读校验后再安排。不在创建阶段执行目标，不重配源业务数据、不修改无关入口；已有入口保留真实 ID 和修订。
   “关闭游戏”“关闭工具软件”使用任务库“默认”类别的内置动作。它们关联前面最近一个快捷任务所属的软件，连续收尾项沿用该任务；不能放在列表开头。按真实调用识别软件，不按标题或模型猜测，不询问进程名、路径或 PID。用户只说关闭游戏时不能同时关闭工具软件。
5. 创建、改时间或改执行列表，先 `scheduler.preview` 核对真实引用、顺序及接下来执行时间，再按当前权限模式写入。用户已明确要求设置且条件齐全就执行，不额外索要一次确认。更新先读最新修订，保留未修改的规则、名称和执行项标识；不默默恢复暂停状态。
6. 写入以返回的 `registration: verified` 且无错误为依据；创建还需 `enabled: true` 才能说会定时执行。失败或结果不明先读取核对，修订冲突先重读并重新应用用户所需变更，不盲重试或改名重复创建。

## 回答和边界

- 提问走 `user.ask`，正文不重复；等到真实答复再进行依赖该选择的写入，预选项不算答复。
- 完成时简短说明任务、时间和必要的执行顺序，例如“已设置每天 20:00 依次运行「委托」「领奖」。”不展示 ID、修订、系统路径、审批术语或后台实现说明。
- 指定日期只登记未来的一次运行；只有明确要求立即运行才调用 `scheduler.run_now`。排队只能说已提交，不能说已跑完。使用同一次请求的 `requestKey` 重试，不能换键试跑。
- 暂停停止以后触发，当前一轮需要另行停止；删除只删时间安排，原快捷任务与历史保留。根据请求处理，不把这两项都当成必要确认问题。
- 权限不足只说明需要以管理员身份运行软件；不询问账户、凭据或提权选项，不自行切换执行通道。插件未启用且本轮明确要求创建安排时，可经当前可用且授权的插件管理能力接通所需插件；仅查询或用户要求保持停用时不修改开关。管理能力不存在、启用失败或用户指令冲突时说明具体条件，不伪造接口。
- 查历史时区分已排队、运行中、成功、部分成功、失败、结果不明、已取消。用户没有要求等待就不持续轮询。失败只说真实失败项和原因，不用模板化自责、道歉或内部校验文字代替处理。

## 执行时数据与可行路径

任务库仅列出可定时的入口。旧入口由固定原生命令及等待构成、没有运行期对象引用且保持默认停止策略时，绑定链路会按当前命令契约转成受控计划，并只读校验后准入。搜索不到或预览失败，不等于原快捷任务不存在或用户目标不可实现；用 shortcut.list、shortcut.get 核对原入口，再读取当前接口契约。参数对象需运行时产生的情况，查 bgi.validate_command_plan、bgi.run_host_command_plan / bgi.run_game_command_plan，以稳定命令、明确集合和有界条件修复封装，再预览与注册。保存和只读校验不执行任何命令。当前桥缺少能力时先核对连接、版本及新目录；按实际更新/连接问题报告，不能泛称软件做不到。

意图只来自当前人类目标及其补充：仅要求拉取、刷新或展示数据，用 host 计划，不添加兑换/游戏输入；只有明确授权实际兑换等游戏动作才用 game 计划。用户要求定时安排时，手动快捷入口只是中间产物，不能擅自替代定时交付。新计划不是任意脚本通道，不接纳 XML、程序路径、运行期对象 ID 或自由模板。
